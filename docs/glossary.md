# Glossary / คำศัพท์กลาง

คำศัพท์ต่อไปนี้ใช้เป็นความหมายกลางใน repo นี้ เพื่อให้ชื่อใน README, คู่มือ และ validator สอดคล้องกัน

The following terms are the shared vocabulary for this repository.

| Term | ภาษาไทย | Definition / ความหมาย |
| --- | --- | --- |
| Skill | สกิว | Reusable instructions in a directory whose entry point is `SKILL.md`. / ชุดคำสั่งที่นำกลับมาใช้ได้ โดยมี `SKILL.md` เป็น entry point |
| Skill Guide | คู่มือ Skill | Human-facing documentation in `docs/skills/`, separate from agent instructions. / เอกสารสำหรับคนใน `docs/skills/` ที่แยกจากคำสั่ง agent |
| Category | หมวด | The single primary directory grouping a skill, such as `agents` or `nextjs`. / directory หลักหนึ่งเดียวที่ใช้จัดกลุ่ม skill |
| Group Install | ติดตั้งแบบกลุ่ม | Installing multiple named skills with repeated `--skill` flags. / การติดตั้งหลาย skill ด้วย `--skill` ซ้ำกัน |
| Source of Truth | แหล่งข้อมูลหลัก | The canonical file that owns a rule or behavior. For a skill, this is `SKILL.md`. / ไฟล์หลักที่เป็นเจ้าของกฎหรือ behavior |
| Skill Index | ดัชนี Skill | Generated catalog at `docs/skills/README.md`, grouped by category. / สารบัญที่สร้างอัตโนมัติและแบ่งตามหมวด |
| Validator | ตัวตรวจสอบ | A deterministic check that detects invalid metadata, missing guides, and stale generated files. / การตรวจแบบ deterministic สำหรับ metadata เอกสาร และไฟล์ generated |
| Workflow Orchestrator | ตัวควบคุมเวิร์กโฟลว์ | The explicit control plane that owns classification, routing, transitions, persisted state, gates, resume, and completion. / control plane ที่เป็นเจ้าของการจำแนก route, transition, state, gate, resume และ completion |
| Stage | ขั้นงาน | One persisted state in an engineering workflow with declared entry, input, discipline, output, exit, failure, and next-state contracts. / สถานะงานหนึ่งขั้นที่มี contract สำหรับเข้า ทำงาน ออก ล้มเหลว และไปต่อ |
| Gate | ด่านตรวจ | A bounded evidence review that must pass before a workflow advances; design, code, and system gates have independent budgets. / การตรวจหลักฐานแบบมีจำนวนรอบจำกัด โดย design, code และ system แยก budget กัน |
| Worker | ผู้ปฏิบัติงาน | In `engineering-workflow`, a single invocation of an installed external specialist that owns discipline work but never chooses the orchestrator's next state; in `implement-tickets`, a harness subagent assigned to build one ticket. / ใน `engineering-workflow` คือการเรียกใช้ external specialist หนึ่งครั้งที่ทำงานตาม discipline แต่ไม่มีสิทธิ์เลือก state ถัดไปของ orchestrator; ใน `implement-tickets` คือ harness subagent ที่ได้รับมอบหมายให้สร้างงานของ ticket หนึ่งใบ |
| Wave | รอบงานขนาน | A group of tickets that can run together after their blockers pass and their touch sets do not overlap; serial is the default mode and gives each ticket its own wave, and `--parallel` opts in to waves built from blockers and touch sets. / กลุ่ม ticket ที่ทำงานพร้อมกันได้เมื่อ blocker ผ่านและ touch set ไม่ชนกัน; ค่าเริ่มต้นคือ serial ซึ่งแยก ticket แต่ละใบเป็นหนึ่ง wave และ `--parallel` เลือกใช้ wave ตาม blocker และ touch set |
| Touch set | ชุด path ที่แก้ไข | A ticket's paths marked `(edit)`, `(new)`, or `(edit from NN)`; it is a planning baseline, not an approval boundary; wave planning uses it to avoid concurrent edits. / path ของ ticket ที่ระบุ `(edit)`, `(new)` หรือ `(edit from NN)` ซึ่ง wave planner ใช้หลีกเลี่ยงการแก้ไขพร้อมกัน โดยเป็นเพียงเส้นฐานของการวางแผน ไม่ใช่ขอบเขตการอนุมัติ |
| Extra | ไฟล์ส่วนเกิน | A file a worker changed beyond its ticket's declared touch set; the orchestrator measures it from the branch diff, accepts it automatically unless it is on the deny-list, over the cap, or a real conflict, and reports it. / ไฟล์ที่ worker แก้เกินชุด path ที่ประกาศไว้ ซึ่ง orchestrator วัดจาก branch diff และรับอัตโนมัติ เว้นแต่อยู่ใน deny-list เกินเพดาน หรือขัดแย้งจริง แล้วรายงาน |
| Drift | การเบี่ยงจากแผน | The event of a ticket having one or more extras, measured from the branch diff against its declared touch set. / เหตุการณ์ที่ ticket มี extra หนึ่งไฟล์ขึ้นไป วัดจาก branch diff เทียบกับ touch set ที่ประกาศไว้ |
| Deny-list | รายการต้องห้าม | The fixed default paths (lockfiles, workflow and GitLab CI files, environment files, decision records) plus a ticket's read-only Context items that no ticket edits; an extra on it parks the ticket. / path ค่าเริ่มต้นที่ห้ามแก้เอง (lockfile, ไฟล์ workflow และ CI, ไฟล์ environment, decision record) บวก Context แบบอ่านอย่างเดียวของ ticket ที่ไม่มี ticket ใดแก้ โดย extra ที่ตรงจะทำให้ ticket ถูกพัก |
| Real conflict | ความขัดแย้งจริง | A squash-merge of a verified ticket that does not apply onto the integration branch; paths that overlap but merge cleanly are accepted and recorded, not deferred. / การ squash-merge ของ ticket ที่ผ่านการตรวจแล้วแต่ apply ลง integration branch ไม่ได้ ส่วน path ที่ซ้อนกันแต่ merge สะอาดจะถูกรับและบันทึก ไม่ถูกเลื่อน |
| Drain round | รอบระบายงานที่เลื่อน | A round inside a wave that runs one deferred ticket alone, in ticket order, from the latest integration commit after a real conflict; the next wave starts only after the wave is integrated. / รอบภายใน wave ที่รัน ticket ที่ถูกเลื่อนทีละใบตามลำดับเลข จาก integration commit ล่าสุดหลังเกิด real conflict และ wave ถัดไปเริ่มเมื่อ wave นี้รวมงานครบแล้ว |
| Touch-set approval block | การบล็อกเพื่อรออนุมัติ touch set | The `BLOCKED (TOUCH_SET_APPROVAL)` state of a ticket parked for a deny-list or cap hit; its work is kept and the person is asked at the end of the wave. / สถานะ `BLOCKED (TOUCH_SET_APPROVAL)` ของ ticket ที่ถูกพักเพราะชน deny-list หรือเกินเพดาน โดยเก็บงานไว้และถามผู้ใช้ตอนจบ wave |
| Hold set | ชุดที่ถูกกัน | The tickets held while a ticket is parked: the parked ticket, every ticket in its wave or a later one whose declared or effective touch set overlaps its effective set, and all their transitive dependants; they are not merged until the hold is released, while all other tickets keep running. / ชุด ticket ที่ถูกกันไว้ระหว่างที่ ticket หนึ่งถูกพัก คือ ticket นั้น ticket ใน wave เดียวกันหรือถัดไปที่ touch set ที่ประกาศหรือ effective ซ้อนกับ effective set ของมัน และ ticket ที่พึ่งพาต่อทั้งหมด โดยจะไม่ถูก merge จนกว่าจะปล่อย hold ส่วน ticket อื่นทำงานต่อ |
| Adapter | อะแดปเตอร์ | A separately installed `implement-tickets-<backend>` skill that runs workers on another backend selected with `--with`. / skill `implement-tickets-<backend>` ที่ติดตั้งแยกเพื่อรัน worker บน backend ที่เลือกด้วย `--with` |
| Backend | แบ็กเอนด์ | The worker execution path: native subagents by default, or an adapter selected with `--with`. / รูปแบบการรัน worker: native subagent เป็นค่าเริ่มต้น หรือ adapter ที่เลือกด้วย `--with` |
| Envelope | ซองผลลัพธ์ | The structured worker result containing `outcome`, `session_id`, `report`, and `usage`. / ผลลัพธ์ worker แบบมีโครงสร้างที่มี `outcome`, `session_id`, `report` และ `usage` |
| Integration gate | ด่านตรวจการรวมงาน | The typecheck and full test suite run after a verified wave is integrated. / การรัน typecheck และ test suite ทั้งหมดหลังรวม wave ที่ผ่าน verification แล้ว |
| External Specialist | ผู้เชี่ยวชาญภายนอก | An installed skill that owns one engineering discipline; the orchestrator supplies context and retains transition authority. / skill ที่ติดตั้งภายนอกและเป็นเจ้าของ discipline หนึ่งด้าน โดย orchestrator เป็นผู้ถือสิทธิ์ transition |
| Artifact Reference | การอ้างอิงอาร์ติแฟกต์ | A repository-relative path plus kind, producer stage, and content fingerprint stored in workflow state instead of the artifact body. / path, ชนิด, stage ผู้สร้าง และ fingerprint ที่เก็บใน state แทนเนื้อหาเต็ม |
| Workflow State | สถานะเวิร์กโฟลว์ | A compact versioned JSON record for workflow identity, classification, execution, evidence references, gates, dependencies, recovery, and revision. / JSON แบบ versioned ที่เก็บ identity, classification, execution, evidence refs, gates, dependencies, recovery และ revision |
| Seam | รอยต่อสำหรับทดสอบ | The one test boundary a ticket's acceptance criteria are exercised at, named on its `**Seam:**` line. / ขอบเขตทดสอบเดียวที่ acceptance criteria ของ ticket ถูกทดสอบผ่าน ระบุในบรรทัด `**Seam:**` |
| Read set | ชุดที่ต้องอ่านของ worker | What a worker must read or change for a ticket, from its `**Context:**` field: spec sections and repository files, each marked read-only, `(edit)`, `(new)`, `(from NN)`, or `(edit from NN)`. The implementers build the list they put in the worker prompt from it and call that list the worker's **read list**. / สิ่งที่ worker ต้องอ่านหรือแก้สำหรับ ticket จากฟิลด์ `**Context:**` คือ spec section และไฟล์ใน repo ที่ระบุ marker อ่านอย่างเดียว, `(edit)`, `(new)`, `(from NN)` หรือ `(edit from NN)` ส่วนรายการที่ implementer สร้างจากมันลงใน prompt ของ worker เรียกว่า **read list** |
| Budget line | บรรทัด Budget | A ticket's `**Budget:**` field: the checker's measured read tokens, acceptance criteria, and modules for that ticket. It records an estimate and sets no limit. / ฟิลด์ `**Budget:**` ของ ticket ที่เก็บค่าที่ checker วัดได้ คือ read tokens จำนวน acceptance criteria และจำนวน modules เป็นค่าประมาณและไม่ได้กำหนดเพดาน |
| `usage_total` | ยอด token ที่ใช้จริง | The tokens a ticket actually cost an implementer, summed over every usage report (each dispatch and each resume) on the path that delivered it, or, for a `BLOCKED` ticket, on the path whose budget it exhausted. For `agy-implement` and `opencode-implement`'s main path it is input + output + thinking/reasoning with cache reads excluded; for `implement-tickets` and `opencode-implement`'s native-subagent fallback path it is the subagent's reported tokens as given, possibly cache-inclusive. / token ที่ ticket ใช้จริงกับ implementer รวมทุก usage report (ทุก dispatch และทุก resume) บน path ที่ส่ง ticket หรือสำหรับ ticket ที่ `BLOCKED` คือ path ที่ใช้ budget จนหมด; `agy-implement` และ main path ของ `opencode-implement` นับ input + output + thinking/reasoning โดยไม่นับ cache read ส่วน `implement-tickets` และ fallback path (native subagent) ของ `opencode-implement` ใช้ token ที่ subagent รายงานตามที่ให้มา ซึ่งอาจรวม cache แล้ว (cache-inclusive) |
| Scenario | สถานการณ์ทดสอบ | One or more indented `Scenario: given … when … then …` examples under a numbered user story in a new spec; each is a concrete, testable example. / สถานการณ์ทดสอบหรือตัวอย่างพฤติกรรมแบบบรรทัดเดียว `Scenario: given … when … then …` ที่เยื้องใต้ numbered user story ใหม่ อย่างน้อยหนึ่งตัวอย่าง และต้องทดสอบได้อย่างชัดเจน |
| Manifest | ไฟล์สรุปแผนงาน | A derived snapshot at `.scratch/<slug>/manifest.json` written after a passing `--write-budget` check, with the spec hash, ticket DAG, and planning-time ticket facts; ticket files remain the source of truth. / snapshot ที่สร้างจากข้อมูลต้นทางใน `.scratch/<slug>/manifest.json` หลัง `--write-budget` ผ่าน โดยเก็บ hash ของ spec, DAG ของ ticket และข้อมูล ticket ตอนวางแผน ส่วนไฟล์ ticket ยังคงเป็นแหล่งข้อมูลหลัก |
| Ticket review | การทบทวน Ticket | A one-pass review by a fresh reviewer that marks each ticket `READY` or `ASK` with the question a new worker would have to ask; it checks ambiguity before the quiz. / การรีวิวหนึ่งรอบโดย fresh reviewer ที่ระบุแต่ละ ticket เป็น `READY` หรือ `ASK` พร้อมคำถามที่ worker คนใหม่ต้องถาม เพื่อตรวจความกำกวมก่อน quiz |
| Retro | การทบทวนผลย้อนหลัง | A review of one finished Run's Primary sources that turns its Misses into Remedies for the Environment. / การทบทวน Primary sources ของ Run ที่เสร็จแล้วเพื่อเปลี่ยน Misses ให้เป็น Remedies สำหรับ Environment |
| Miss | สิ่งที่พลาดหรือเกิดความสูญเปล่า | Something in a Run that went wrong or cost more than it should (e.g. blocking finding, failed verification, BLOCKED ticket). / สิ่งที่ผิดพลาดหรือสร้างต้นทุนเกินจำเป็นใน Run เช่น blocker finding หรือ verification ล้มเหลว |
| Remedy | มาตรการแก้ไขสภาพแวดล้อม | A change to the Environment that stops a Miss from recurring; one of Check, Standard, Pointer, Skill fix, Prune, or Access. / การปรับปรุง Environment เพื่อไม่ให้ Miss เกิดซ้ำ มี 6 ชนิดคือ Check, Standard, Pointer, Skill fix, Prune, หรือ Access |
| Retro Log | บันทึกประวัติการทบทวน | The per-project file docs/retro-log.md recording each Remedy a Retro proposed, its Misses, and outcomes across Runs. / ไฟล์ docs/retro-log.md ประจำโปรเจกต์ที่บันทึก Remedy ทุกตัว, Misses ต้นทาง และผลลัพธ์ข้ามแต่ละ Run |
