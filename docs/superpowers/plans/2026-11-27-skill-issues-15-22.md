# Skill issues #15 to #22 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the eight open issues in `ArrayaWongsaita/skills-issues` (#15 to #22) and the preview-port problem, so part-slides and opencode-delegate report these problems themselves instead of leaving them to trial and error.

**Architecture:** Each issue is its own branch off `main` and its own PR (`Closes ArrayaWongsaita/skills-issues#<n>`), except #15 and #16, which share one. Python script fixes are TDD'd with pytest. Template fixes are TDD'd with vitest: a pure function holds each rule, and the component or check page feeds it. Doc fixes get a pytest check in `tests/test_references.py` when the rule can be pinned to a phrase.

**Tech Stack:** Python 3.12 stdlib + pytest (via `uv`), React + TypeScript + vitest (via pnpm), `gh`.

**Spec:** `docs/superpowers/specs/2026-11-27-skill-issues-15-22-design.md`

## Global Constraints

- Code, comments, docs, commits, PRs and issues in English. Talk to the user in Thai.
- Conventional Commits with the skill as the scope (`fix(part-slides): …`, `fix(opencode-delegate): …`); one commit per change.
- Branch per issue: `fix/<skill>-<slug>`, from an up-to-date `main`. PR body says `Closes ArrayaWongsaita/skills-issues#<n>`; then `gh issue comment <n> -R ArrayaWongsaita/skills-issues --body "Fix: <PR URL>"`.

## Review Focus

1. **A re-run of `scaffold.py --part N` for a Part that already exists, without `--language`:** must not fail or rewrite the Part; it reads the language from that Part's own data file. (Task 2 test `test_rerunning_an_existing_part_without_language_keeps_it`.)
2. **A code excerpt with `…` gap markers:** a gap marker below the box edge counts as a hidden row, and a highlighted line that is wholly hidden is named in the finding. (Task 4 test `a hidden highlighted line is named`.)
3. **An output box (no line numbers) that is too tall:** still reported as `clipped-code`, with hidden lines counted from its height. (Task 4 test `an output box that is too tall is clipped-code`.)
4. **A `failed` turn whose log mentions `ECONNRESET` early but ends with a real error:** only the last lines of the log are read, so an early mention gives no `cause=`. (Task 3 test `test_an_early_connection_reset_gives_no_cause`.)
5. **A phone frame with a wide line:** stays a `scrolling-block` note, never a problem, so an existing clean Part does not start failing on phone width alone. (Task 4 test `a wide line on the phone is a note`.)

/** One row of a code or output box, in px relative to the box's visible area. `line` is null for a `…` gap marker or an output line. */
export type RowGeometry = { line: number | null; bottom: number; right: number; chars: number; highlighted: boolean };
export type BoxGeometry = { width: number; height: number; scrollHeight: number; lineHeight: number; charWidth: number; rows: RowGeometry[] };
export type BoxOverflow = { hiddenRows: number; hiddenHighlight: number[]; wideLines: { line: number | null; chars: number }[]; fits: number };
